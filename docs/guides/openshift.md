# OpenShift Deployment Provider

Open Simple Agent includes a dedicated, opt-in `OpenShiftDeploymentProvider`.
It uses the operator's `oc` context and RBAC boundary, emits the common OSA
ConfigMap/Deployment/Service workload, and adds an OpenShift
`route.openshift.io/v1` `Route`. It does not accept arbitrary manifests or
commands from the Control Plane API.

## Configuration

Set these server-side variables:

| Variable | Purpose | Default |
|---|---|---|
| `OSA_DEPLOY_PROVIDER` | Select `openshift` | `local` |
| `OSA_OPENSHIFT_IMAGE` | Runtime image | required |
| `OSA_OPENSHIFT_NAMESPACE` | Target project/namespace | `default` |
| `OSA_OPENSHIFT_REPLICAS` | Desired runtime replicas | `1` |
| `OSA_OC` | `oc` executable | `oc` |
| `OSA_OPENSHIFT_ROLLOUT_TIMEOUT_SECONDS` | Maximum rollout wait | `60` |
| `OSA_OPENSHIFT_ROUTE_HOST` | Optional explicit Route host | generated by OpenShift |
| `OSA_OPENSHIFT_ROUTE_TLS_TERMINATION` | `edge`, `reencrypt`, `passthrough`, or empty for HTTP | `edge` |
| `OSA_OPENSHIFT_ROUTE_INSECURE_EDGE_POLICY` | `Allow`, `None`, or `Redirect` | `Redirect` |

For a durable Control Plane, configure PostgreSQL and run
`osa-cp-migrate` before startup. `OSA_PERSISTENCE_POLICY=shared` accepts the
Kubernetes or OpenShift provider, but SQLite and process-local repositories
remain invalid for shared deployments.

The runtime image must run as a non-root user and the target project must
permit the generated restricted security context. Provide runtime secrets as
`KubernetesSecretRef` references; secret values are never copied into the
bundle ConfigMap.

The repository includes a manual `.github/workflows/openshift-acceptance.yml`
workflow. It remains a no-op unless the repository secret
`OSA_OPENSHIFT_KUBECONFIG` and repository variable
`OSA_OPENSHIFT_ACCEPTANCE_IMAGE` are configured. The kubeconfig is written
only to the ephemeral runner with private file permissions.

## Current validation status

Unit tests cover provider selection, Route generation, TLS/host validation,
secret references, and the shared/local persistence boundary. A real OpenShift
acceptance run is still required against a selected OpenShift version and
cluster to validate Route admission, SCC/security-context policy, RBAC,
rollout/reconciliation, and operator ownership. Until that environment is
selected, standard Kubernetes remains the CI-validated production target.
